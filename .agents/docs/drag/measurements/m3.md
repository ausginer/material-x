# M-3 — the four compositions, two baselines, and the `DEV` strip

**Status: answered, 2026-08-02 (harness revised 2026-08-03). The tree-shaking
claim holds; composition costs 0.26 kB; migrating from the shipped package costs
2.44 kB.**

M-3 ([05](../contract/05-lifecycle-invariants.md) §Measurements owed) asks what
the composed entrypoints actually weigh, whether the import graph is what
[03](../contract/03-feature-composition.md) §Tree-shaking claims, and — carried
into this phase by the plan — how the dev-only assertions are meant to leave a
production build.

## Harness

[`packages/drag2/bench/size/measure.ts`](../../../packages/drag2/bench/size/measure.ts),
run by `just size` and asserted by
[`tests/bench/size.node.test.ts`](../../../packages/drag2/tests/bench/size.node.test.ts).

**One declaration per composition**: its named imports, its budget, and the
modules its graph must and must not contain. Every input 05 lists as a
reproducibility precondition is a value in that file rather than a flag
somewhere:

- **The exact import statement of each composition** is its `imports` map, keyed
  by public subpath. The two *baselines* carry `entry` instead — a checked-in
  module — because neither is expressible as a set of imports: baseline A has to
  assemble a slot record by hand, and baseline B is a different package.
- **Bundler/target/minifier**: Rolldown at the lockfile version, `platform:
  'neutral'`, ESM out, built-in minifier. **Compression**: Brotli via
  `node:zlib` at default quality. **Aliases**: none.
- **Repetition policy**: none, and none is needed. The pipeline is
  deterministic, and the test asserts byte-identical output across two runs
  rather than assuming it.
- **Module-graph assertions** naming every optional module that must be absent
  from each composition, plus the converse so absence cannot pass vacuously.

**Why not `size-limit`** is written up in
[`.agents/docs/measure/brief.md`](../../measure/brief.md), which is the brief for
a repository-wide replacement. In short: Size Limit reports a number and has no
vocabulary for the graph, so the half of M-3 that is not a number would have to
be declared a second time, in a second format, against a second copy of the same
fixture list. Its `import` option *does* work — it was measured, and agrees with
this harness to the byte — but only for a plugin willing to rename itself
`size-limit-esbuild`, because the capability gate is a name comparison.

One artifact of getting here: the numbers below are ~20 bytes lower than the
first version of this measurement, which used checked-in fixture modules and was
therefore also weighing each fixture's own `mount` wrapper.

## Numbers

Brotli-compressed bytes of the minified bundle:

| fixture | size | modules | vs minimal |
| --- | --- | --- | --- |
| minimal | **9.33 kB** | 29 | — |
| minimal + `layoutAnimation()` | 9.74 kB | 30 | +0.41 kB |
| minimal + `landing()` | 9.60 kB | 30 | +0.27 kB |
| complete | **10.09 kB** | 33 | +0.76 kB |
| baseline A — feature-matched, non-composed | 9.83 kB | 28 | — |
| baseline B — shipped `@ydinjs/drag` `sortable.js` | **6.89 kB** | 26 | — |

**The two baselines answer different questions and are never substituted for
each other.**

**Since measured (2026-08-03):** the sortable lift mode changed from `LIFT_FLAT`
to `LIFT_FAITHFUL` and `acquireLift` gained one style write, moving minimal to
9.34 kB and complete to 10.11 kB. Every budget still holds. The numbers above
are left as measured; the live figures are whatever `just size` prints.

## Answer 1 — the tree-shaking claim is real

Each optional feature adds only itself: `layoutAnimation()` 0.41 kB,
`landing()` 0.27 kB, one module each. The minimal composition pulls **29
modules** and none of `landing`, `layout-animation`, `placeholder` or `handle`
appear in its graph — asserted, not inferred from the delta.

The complete composition is **0.76 kB over minimal**, so a consumer who wants
none of it is not carrying it.

## Answer 2 — composition costs 0.26 kB (2.6%)

Baseline A holds the features constant and removes only the composition layer:
the branded factories are invoked directly and their contributions flattened by
hand into the slot record, with no `assemble()`, no single-writer claims, no
unwind and no validation.

**Complete 10.09 kB against non-composed 9.83 kB: 0.26 kB, 2.6%, five extra
modules.** That is what the feature model costs in bytes, and it buys the export
topology that makes answer 1 possible — the same measurement showing a consumer
who installs nothing saves 0.76 kB.

A smaller result fell out of it: the built package tree-shakes
`createSortableBehavior`, the non-composed seam the tests drive, away entirely.
The internal seam costs a consumer nothing.

## Answer 3 — migrating costs 2.44 kB (+35%)

Baseline B is the size a consumer is moving *from*: 6.89 kB for the shipped
`sortable.js` against 9.33 kB for the minimal composition. It is **not**
feature-equivalent — it is one non-tree-shakable module with its own feature set
— so this is a migration figure and nothing else. Quoting it as though the new
package were 35% worse at the same job would be wrong in both directions: it
does less than `complete` and more than `minimal`.

The honest sentence is: **the rewrite costs a consumer 2.44 kB of compressed
JavaScript**, and what that buys is in
[01](../contract/01-construction-ownership.md) and
[02](../contract/02-kernel-behavior-contract.md), not here.

## Answer 4 — the `DEV` strip, which was the carried decision

Phase 2 landed the dev-only assertions behind a module constant resolved from
`process.env.NODE_ENV` inside a function, with the note that this does not
actually strip them. M-3 measured what a consumer could recover:

| form | minimal fixture | recovered |
| --- | --- | --- |
| `resolveDev()` reading `process.env.NODE_ENV` | 9.66 kB | — |
| same, consumer defines `NODE_ENV=production` | 9.63 kB | **0.03 kB** |
| bare `__DEV__`, substituted at build | **9.33 kB** | **0.33 kB (3.4%)** |

**A minifier cannot fold a call.** With the old form the define replaced the
string and nothing else: every guarded block survived, and every assertion still
*ran* in production. The 30 bytes recovered were the literal `"production"`.

The mechanism is now a bare `__DEV__` identifier substituted at build time —
`false` in the published bundle (`tsdown.config.ts`), `true` in every in-repo
build and test run. `kernel/dev.js` stops being emitted at all.

**The trade, stated plainly:** a consumer cannot turn the assertions back on.
That costs nothing today, because they check *behavior authoring* — frame-part
shape, reset exhaustiveness, unconsumed staged values — and behavior authoring
is not on the public surface. The day it is, this needs a dual build under an
`exports` condition, or an inline `process.env.NODE_ENV` comparison at each site
instead of a shared constant. There is deliberately no
`typeof __DEV__ === 'undefined'` fallback: that guard is exactly what defeated
folding before, and a missing define should fail loudly at import rather than
silently ship the assertions.

## Budgets

Set from this measurement with ~0.3 kB of headroom, as `limit` on each check in
`.size-limit.json`, enforced by `just size`. They are deliberately tight: the
point of a budget here is to notice a module appearing in a graph, and 0.3 kB is
roughly one such module.

## What would reopen this

- Any new public subpath, which changes what "minimal" can mean.
- A feature that stops being one module — the per-feature deltas are
  one-module deltas.
- A behavior-authoring public surface, which changes the `DEV` decision before
  it changes the sizes.
