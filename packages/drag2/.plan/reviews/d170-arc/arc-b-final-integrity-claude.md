## Methodology note — a tree-contamination hazard, not a drag2 defect

While running the kernel suite repeatedly in the live checkout, I hit a batch of `tests/kernel/seams.node.test.ts` failures shaped like `expected 3 to be 0` / `expected 3 to be 1` (`ACTIVE`/`PENDING`/`IDLE`'s numeric values) that reproduced consistently under default parallelism and vanished under `--no-file-parallelism`. Chasing it: `git status` on `/workspaces/material-x` showed `src/kernel/kernel.ts` live-modified — `this.#frames.commit(ACTIVE)` read as `this.#frames.commit(PENDING)` at the release-seam line, uncommitted, with no corresponding entry in `git diff 185fb371..25be674c`. This was not a build-cache artifact (clearing `.vite` did not fix it) and not present in a freshly created worktree at the same commit (which passed 86/86 immediately). `arcb-reviewer`, running concurrently in this session, confirmed the edit was not theirs — their own mutation probes run in two separate detached worktrees, both `git status`-clean — and pointed at a concurrently-running cleanup pass as the likely source, evidenced by an untracked `arc-b-final-cleanup-claude.md` appearing in the same tree. I flagged this to `arcb-reviewer` and to `main`; I did not revert the file myself, since I could not tell whether the owning pass was mid-run.

**Why this doesn't touch the findings below.** Everything load-bearing in this report was independently re-verified in one of two ways immune to that hazard: `git show 25be674c:<path>` (reads the commit object directly, never the working tree) for every prose/contract comparison, and a `git worktree add … 25be674c --detach` checkout, separate from both the contaminated main tree and `arcb-reviewer`'s own worktrees, for every mechanical run (`tsc --noEmit`, the full `vitest` suite, `bench/size/measure.ts`). Both came back clean; the numbers quoted under **Mechanical verification** below are from that worktree.

**Incidental exposure, disclosed.** In the course of checking whether the working tree matched `HEAD`, I ran `git diff 25be674c HEAD -- packages/drag2/` to rule out drift from commits after the reviewed range. That diff's output included most of the newly-added `arc-b-feature-proof-claude.md` — the file I was instructed not to read, being from an invalidated run. I did not seek it out and did not use anything from it to form a finding: every claim in this report was derived from `git show`-pinned contract text, direct source reading, and my own mechanical runs, all of which either preceded that exposure or were re-derived independently afterward in the clean worktree. Flagged here rather than concealed, per the same honesty this pass is asking of the record.
