## Findings

### cleanup-1 — tier C — `preparationValid()`'s identity conjunct has no falsifier in the current suite, and the shape it forces on `SeamDriver`'s construction is entirely contingent on that gap

**Current behavior/contract.** `Kernel.#preparationValid()` (`src/kernel/kernel.ts`) composes three conjuncts: `!this.#bracket.closed`, `!this.#operation?.cancelRequest`, and `this.#frames.current.operation === this.#pinned`. `#pinned` is captured in `Kernel.#begin()` rather than moved into `FrameTransaction`, so `SeamDriver`'s constructor takes a `begin: () => void` closure (over `Kernel.#begin`) as a **fifth** collaborator instead of calling `frames.begin()` directly.

**Why it is a problem.** `CONTRIBUTING.md` §1.1's litmus test asks, of any runtime state: *is this state reachable through correct use of the public contract?* `tests/COVERAGE.md`'s own B-0 mutation table (added in this range) states the answer for this conjunct directly: `current.operation === pinned` dropped → **"none, and none could be written."** `#retireOperation` nulls `current.operation` and clears `#pinned` with nothing between them; every other path that could desynchronize them is already caught by the other two conjuncts. That is the reachability gate's own vocabulary for a deletion candidate — not a question of ownership (§1.1 (b) is never reached, since (a) already fails).

The record does not hide this: `00-index.md` carries it as **F-349** ("no reachable falsifier") and **F-350** ("the driver takes a fifth collaborator, because the pin stayed behind"), both explicitly left open with the stated reason that landing the deletion in the same commit that discovered it would make the deletion unreviewable. That is a legitimate reason to defer, not to absorb silently — and it is why this is reported as confirmation of an open item rather than a new one.

**Evidence.** `packages/drag2/tests/COVERAGE.md` (this diff): *"The third conjunct has no reachable falsifier, so `#pinned` did not move."* `packages/drag2/src/kernel/seams.ts:240-252` (the five-parameter constructor and its "collaborators rather than one record" rationale). `packages/drag2/src/kernel/kernel.ts:2476-2498` (five-argument `new SeamDriver(...)`). `packages/drag2/.plan/contract/00-index.md` F-349, F-350 (already open).

**Required property.** Either the conjunct is shown reachable by a state this suite does not yet construct, or it is deleted along with the `#pinned` relocation and `begin: () => void` collapses back to `frames.begin` — a four-collaborator driver. This is an architect/owner disposition (§13-adjacent: it touches an invariant the kernel currently asserts), not a cleanup-lens fix; reported per the instruction to name violated properties, not prescribe fixes.

### cleanup-2 — tier C — a rewritten internal comment narrates history with strikethrough, against `documentation.md` §5.2

**Current behavior/contract.** `tests/kernel/vocabulary.node.test.ts:146-149` (rewritten in this range, replacing the entry that named `NO_STAMP` as internal vocabulary):

```
// The phase *constants* are published; the entity the kernel keeps them in
// is not. ~~`NO_STAMP`~~ went with the slot it named a gap in (D-181): the
// phase reaches a commit as an argument, so there is no absent-phase
// sentinel left to keep out of the published vocabulary.
```

**Why it is a problem.** `documentation.md` §5.2 governs internal comments: *"No strikethrough. A superseded sentence is deleted here."* and *"Do not narrate history: no 'used to', 'was changed', 'replaces', 'previously'... If a past decision holds reasoning still needed to understand the code, restate the reason, not its provenance."* This comment does the opposite of both: it strikes through a deleted name and narrates that it "went with the slot it named a gap in" rather than simply stating, in the present tense, that no absent-phase sentinel exists because the phase is now an argument of `commit`.

This is not an isolated slip — it is one instance of a convention this specific file applies throughout (`~~SeamRejection~~`, `~~toDraggableError~~`, `~~src/kernel/dev.ts~~`, `~~Four~~ **two**`), and the file's own last `it` (`'should name that module wherever prose names the binding's home'`) treats `~~name~~` as a recognized, deliberately-excluded marker for "a deliberate reference to something retired." So the file has a pre-existing, self-aware local dialect that predates this range and is not something Arc B invented. What Arc B did add, inside that dialect, is new historical narration (*"went with the slot it named a gap in (D-181)"*) that the rule in §5.2 forbids regardless of the surrounding convention — the bare pointer `(D-181)` is permitted on its own, but the clause built around the strikethrough is provenance, not a restated reason.

**Evidence.** `packages/drag2/tests/kernel/vocabulary.node.test.ts:146-149`; confirmed new to this range via `git log -p 185fb371..25be674c -- tests/kernel/vocabulary.node.test.ts`, which shows the line replacing a non-narrating entry (`'kernel-private frame state': ['NO_STAMP']`).

**Required property.** An internal comment states the current constraint in the present tense (documentation.md §5.2, §5.3's first test: *"if this became false tomorrow, is deleting it enough"* — here deleting it is enough, so it is comment territory, but its content must not narrate). This is a documentation-discipline finding, not a runtime-machinery one; tier C because it affects no consumer and nothing the repository relies on depends on the sentence's exact wording, only its future maintainers.
