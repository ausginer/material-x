# D-162 closure — package coherence pass (the `InheritedSpace` re-export)

Files read at `e4e835ba`, diffed against baseline `c168126d`. Subject: the one consequence the amended D-162 record names but does not spell out — `sortable/feature.ts` now re-exports `InheritedSpace`, a kernel-declared type, as part of its own (middle-tier) public surface.

## Scope

Covered: whether this re-export is a correct consequence of the drag2 package's existing tier/layering rules, or an unintended widening of `sortable/feature`'s public surface / a cross-tier leak. Precedent check against `free-drag/feature.ts` and against `sortable/feature.ts`'s own prior re-exports. Sanity checks for duplicate declarations, naming collisions, and downstream consumers newly forced to reach into the kernel directly.

Not covered (out of my lens, belongs to the feature-proof pass): whether adding a fifth parameter to `DisplacementReport` is itself the right shape, whether the amended D-162 correctly supersedes the held D-162, or the byte-budget arithmetic in the plan's ledger entry.

## Finding — no drift

**integrity-1 (tier: no finding — verdict recorded)**

**Claim checked:** does `sortable/feature.ts` exporting `InheritedSpace` (`packages/drag2/src/sortable/feature.ts:36`) violate the drag2 tier-boundary rules, or does it apply them correctly?

**Verdict: (a) — correct, unavoidable consequence of rules already in force.** Two independent instruments, both pre-existing and both unrelated to this remediation, forced this export and no other outcome was available:

1. **`tests/docs.node.test.ts`** runs TypeDoc over drag2's declared public entries (`typedoc.json`, `entryPoints`) and fails on any public type that structurally reaches an unexported one (`packages/drag2/tests/docs.node.test.ts:1-14`). `DisplacementReport` — published from `sortable/slots.ts` and re-exported by `sortable/feature.ts` — is a function type whose fifth parameter is `space: InheritedSpace` (`packages/drag2/src/sortable/slots.ts:47-52`). Once `report`'s signature names the type, `sortable/feature.ts`'s own entry point structurally reaches it, and TypeDoc's per-entry closure check has no other way to pass than exporting it there.
2. **`tests/kernel/vocabulary.node.test.ts`** independently asserts that every `../kernel/*` import inside `src/sortable/` is either already-published kernel vocabulary or an explicitly enumerated internal (`packages/drag2/tests/kernel/vocabulary.node.test.ts:1-25`). The remediation adds new `import type { InheritedSpace } from '../kernel/presentation.ts'` lines to `runtime.ts`, `linear-shift.ts`, `slots.ts`, `y.ts` and `xy.ts`. `InheritedSpace` was already exported at the kernel root (`packages/drag2/src/kernel.ts:109-118`, unchanged by this diff — `kernel.ts` does not appear in `e4e835ba`'s file list), but was missing from the test's `PUBLISHED_TYPES` mirror list, so the new imports forced the list to catch up (`git diff c168126d e4e835ba -- packages/drag2/tests/kernel/vocabulary.node.test.ts`).

Both instruments pass at `e4e835ba`: `npx vitest run tests/kernel/vocabulary.node.test.ts tests/docs.node.test.ts` → 2 files, 14 tests, no type errors.

**Precedent, not novelty.** The export follows the exact pre-existing pattern in the same file: `sortable/feature.ts` already re-exported `Disposer` (from `kernel/lifetimes.ts`), `DOMRealm` (from `kernel/realm.ts`) and `LandingContext`/`LandingHandle`/`LandingStart` (from `kernel/spec.ts`) before this change, each with the identical `export type { X } from '../kernel/Y.ts';` shape and a comment invoking the same rule the new line's comment cites ("a type this entry's surface reaches is a type an installer author must be able to name"). `free-drag/feature.ts` mirrors the same pattern for its own reached kernel types (`Disposer`, `DOMRealm`, `LandingContext`, `LandingHandle`). This is the governing rule stated in `packages/drag2/.plan/reviews/phase-23/middle-tier-boundary-claude.md` §0: _"Publish what the protocol's producers need in order to produce."_ A third-party sink author implementing `DisplacementReport` is exactly such a producer, and could not previously name the type of their own function's fifth parameter without reaching into `../kernel/presentation.ts` directly — which the vocabulary test would have refused. The new export closes that gap rather than opening one.

**The `free-drag` asymmetry is not a counter-example.** `free-drag/feature.ts` does not re-export `InheritedSpace`, even though `free-drag/spec.ts` and `free-drag/geometry.ts` consume `ActivationScope.inheritedSpace` internally. Checked directly: `free-drag/geometry.ts`'s `buildGeometry`/`buildRequest` take `space: InheritedSpace` as a parameter, but project it into `localDeltaX`/`localDeltaY` (plain numbers) before returning `DragGeometry`/`FreeDragRequest` — the public consumer-facing shapes never carry the `InheritedSpace` type itself (`grep InheritedSpace packages/drag2/src/free-drag/slots.ts` → no hits). Free drag's public surface genuinely does not reach the type, so it has nothing to republish. The two middle tiers disagree here because D-162's chosen delivery mechanism — the space "rides with the vector" as a raw, unprojected argument on the published callback (§3 of `displacement-coordinate-space-claude.md`) — is a different design choice from free drag's, not an inconsistency in how the two tiers apply the publication rule.

**No duplicate declaration, no naming collision, no new kernel reach-through.** `InheritedSpace` has exactly one declaration (`kernel/presentation.ts:343`); every other site (`kernel.ts`, `sortable/feature.ts`, and the five internal `sortable/*.ts` importers) re-exports or imports that same declaration. No cross-package consumer in this repository currently imports `DisplacementReport` or `InheritedSpace` from drag2 (`grep -rl DisplacementReport packages/*/src packages/*/tests` outside `packages/drag2/` → no hits), so there is no downstream break to evaluate. If anything, the new export removes a reach-through that would otherwise exist: a third-party sink author can now name the parameter type from `sortable/feature.ts` instead of importing from `../kernel/presentation.ts` directly.

**One thing noticed but out of this diff's attribution, recorded for completeness only.** `tests/docs.node.test.ts`'s own header says "TypeDoc runs over the eight public entries" while `typedoc.json`'s `entryPoints` currently lists twelve. Neither `docs.node.test.ts` nor `typedoc.json` is in `e4e835ba`'s changed-file list, and the count was already twelve at baseline `c168126d`, so this predates the D-162 closure and is not a consequence of it — not reported as a finding of this pass, named only so it is not mistaken for silence.

## Null result, stated explicitly

The specific consequence flagged for this pass — `sortable/feature.ts` publishing `InheritedSpace` — is verdict (a): a correct, forced application of the drag2 package's existing publish-what-producers-need rule, evidenced by two independent pre-existing instruments both passing, and matching the established precedent for how this exact file republishes kernel types. No package-coherence drift found outside the immediate fix.
