# `@ydinjs/box-quad` — the record

The package's argument, alternatives, measurements and findings. The current-state documents are [`contract/`](contract/) and the package `README.md`; this file carries what they evict, append-only and dated.

**Decision ids are `BQ-n`**, package-qualified rather than the bare `D-n` used in [`packages/drag2/.plan/`](../../drag2/.plan/plan.md). The two namespaces are independent and box-quad's decisions are cited from drag2, so an unambiguous prefix costs one character and removes a real reading hazard.

**A decision is atomic** ([`documentation.md`](../../../.agents/docs/documentation.md) §6): a substantive amendment mints a superseding decision and the old one goes `inactive`; wording and citations are corrected in place.

| **BQ-5** | **The retained-`Ancestry` formulation is declined; BQ-2 stands unchanged.** Record [`07-D-ancestry-formulation-claude.md`](reviews/07-D-ancestry-formulation-claude.md). | **BQ-6** | **Unimplemented (Iteration D).** **Supersedes BQ-4.** **The cache is removed: `cache()`, the `recache` parameter, `BoxCache`, `InternalCache` and `Space.ownerDocument` all go, and [`contract/05-cache-semantics.md`](contract/05-cache-semantics.md) is deleted rather than amended.** Record [`08-D-cache-utility-claude.md`](reviews/08-D-cache-utility-claude.md). That commit split the API and made `relativeTo` a caller-held **`Box`** — so the shared target is now measured once by the caller by construction. **The refactor that gave `cache()` its current form deleted its only documented use case, and the mechanism was carried across unexamined.** BQ-4 is right that the reshaping was deliberate; it was deliberate about the cache's _form_, callable versus map, and never reached utility. **No consumer**: `cache(` occurs twice outside tests — its definition and the generated `index.d.ts` — and `@ydinjs/drag2`, the one dependent, passes none at its one call site. **No hit rate, structurally**: a cache pays only when an element is measured twice between two writes, and no plausible batch shape does that — N candidates are each measured once, the next rebuild follows a layout change that voids the epoch, and the two shapes that _did_ hit (a shared container, a parent used as both target and reference) are exactly the ones `projection`'s `Box` parameter converted into retention. **Measured, and the mechanism is not a no-op**: repeated measurement gets **no repeat discount** from the browser (118.4 µs against a distinct element's 117.7 at depth 12), so a hit is worth **676×** — but `out.set(kept)` is **0.025 µs against the hit's 0.175**, so **`Box` retention beats the cache 7× on the cache's own best case**, and 4700× on the cold one. | **BQ-7** | **Superseded by BQ-8, 2026-08-31 — upheld against a cheaper alternative, but its property list did not pin the fact that now justifies it.** **Unimplemented (Iteration D).** **Supersedes BQ-2.** **Cardinality stays one — but the allocator becomes caller-owned variable capacity, so that is a current limit rather than a surface commitment.** Record [`09-D-boundary-cardinality-claude.md`](reviews/09-D-boundary-cardinality-claude.md). Eight boundaries at depth 30 are not measurably more expensive than none (293.7 µs against 307.1), the spread is ±10% and unordered, and every figure is dominated by ~10 µs per node of `getComputedStyle`. N boundaries in one walk agree with N singular walks **to 12 decimal places**, from one observation, retaining nothing. It is a coherent primitive. **Falsified on bytes by 3×**: against the cacheless baseline K, one boundary is **+52 B** and N boundaries **+165 B**, and two leaner dispatches came out _worse_ — an array parameter with `indexOf` at +171, a single accumulator with a closing right-division at +208, the latter also numerically fragile on a degenerate ancestor. **The hypothesis is right that caller-owned storage is free, and that is precisely why it does not help: the cost is dispatch, not slots.** **It loses on four grounds.** **At this price the better purchase is one already declined** — arm L at 1312 B sits within 7 B of the retained `Ancestry` at 1305, which BQ-5 refused; multi-boundary is the _safer_ of the two at equal money, retaining nothing and pinning no DOM, but buys strictly less generality, and neither has a consumer. **Variable capacity adds a failure mode fixed cardinality cannot have**, demonstrated both ways in a browser: `out.set()` throws `RangeError` **after** committing slots 0–12, breaking the atomic-output guarantee with an escaping exception, while per-slot writes drop silently and return `true` with a space missing — BQ-3's condemned class. | **BQ-8** | **Superseded by BQ-9, 2026-08-31 — its one ground was a coupling in the design, not a fact about the problem.** **Unimplemented (Iteration D).** **Supersedes BQ-7.** **The boundary capability survives deletion, but only because a boundary need not be measurable — so that becomes binding.** Record [`10-D-two-measurement-alternative-claude.md`](reviews/10-D-two-measurement-alternative-claude.md). The hypothesis under test was that the shipped API already produces both of D-164's spaces: `coordinates(visual, visualBox)` for the space above the visual, `coordinates(item, itemBox)` for the space above the item, two consecutive reads in one task. **It nearly holds, and the honest figures favour it.** The second measurement reproduces the boundary walk **bit for bit** — `toBe`, not a tolerance — because it composes the same nodes in the same order; the snapshot question answers itself, since two consecutive statements admit no intervening layout. **It is 51 B cheaper end to end**: with the full drag2 shape bundled in, today's single-space consumer is 1287 B, two measurements **+9**, guarded on `visual === item` +23, and BQ-7's boundary **+60**. **Its runtime cost is real and affordable**: the second call is a second style walk — +15.8 µs at depth 5, +69.3 at 15, +144.7 at 30, against BQ-7's flat ~+23 — once per lift, in a path that already takes a computed style and mutates the visual, and **zero** in the default composition, which never makes the second call. No extra layout flush is taken: nothing writes between the reads, and the cost scales linearly with depth, which is style traversal and not a flush. **It is declined on one ground.** `coordinates` returns `false` for an element with no single principal box, but **the space inherited by that element is defined regardless** — it is a property of the chain, not of the element's box. Verified in Chromium: a `display: contents` item with a descendant visual and an inline item fragmented across five lines both yield the correct `[2,0,0,3]` from the boundary walk and **`false`** from a direct measurement. That is not an exotic shape — a wrapper that renders nothing and presents an inner node is the archetypal reason to name a `visual`, it works end to end today because nothing measures the item, and under the alternative drag2 must choose between refusing a working configuration at activation and silently reinstating F-227. Recovery at the consumer means measuring the item's parent, which is correct only when the item contributes nothing, needs a loop when the parent is also `display: contents`, and obliges a consumer to walk `assignedSlot ?? parentElement ?? host` — the duplicated traversal this package exists to prevent, and closed to a behavior module by drag2's D-85. **The membership check is explicitly not the ground.** BQ-7's off-chain `false` exists because the item's space is derived from the _visual's_ walk; the alternative asks the item about its own ancestry and needs no such condition, and a visual outside the item's subtree measures correctly under it. The check is kept because the walk must already know when it passes the boundary, so reporting it costs nothing and turns an invariant drag2 owns but does not enforce into a recognized refusal — a modest gain, never a justification. **Required properties**: everything BQ-7 required, carried forward unchanged — cardinality one; caller-owned capacity via `box(boundaries = 0)`; `BOX_LENGTH` constant for the ordinary measurement; an off-chain boundary a recognized `false`; insufficient capacity recognized rather than discovered by a partial write; a future N purely additive — **plus, newly binding: the boundary space is produced from the chain alone**, so a boundary with no principal box of its own still yields its space and does not turn the measurement into a `false`. **Figures are unchanged from BQ-7**: +55 B as consumed against BQ-6's −46, net −9. **Void as a ground**: separating `Space` from `Box` makes the item's ancestry obtainable without measuring it, for fewer bytes — see [`11-D-first-class-space-claude.md`](reviews/11-D-first-class-space-claude.md). | pins the one fact that makes the capability worth its 51-byte premium, so an implementation cannot discard it as an incidental behaviour                                          |
| **BQ-9** | **Unimplemented (Iteration D).** **Supersedes BQ-8.** **`Space` becomes first-class and `Box` becomes a pure measurement; the ancestry boundary is deleted rather than implemented.** Record [`11-D-first-class-space-claude.md`](reviews/11-D-first-class-space-claude.md). BQ-8 kept the boundary on exactly one fact — an element can have a well-defined inherited space and no measurable principal box, so the item's space could not be had by measuring the item. **The fact is true and the conclusion was not**: it is an artifact of ancestry computation being welded to box measurement, which the source already splits internally at `composeLinearMatrix` versus the rest of `createSpace`. Publishing that seam gives `ancestry(element, out)`, which **reads no layout and never touches the element's own box** — verified in Chromium, where a `display: contents` element and one fragmented across four lines both return `false` from `coordinates` and `true` with the correct `[2,0,0,3]` from `ancestry`. **It is cheaper than the capability it replaces.** `Space` is `Float64Array(5)` — `[a, b, c, d, ancestorZoom]` — and `Box` drops to **8 slots, exactly what `projection` reads**: as consumed the package is **+16 B** with the ancestry argument required and **+38 B** with it optional, against BQ-8's +55; end to end with drag2's shape bundled in, **+34 and +56 against BQ-8's +61**. The saving is structural — five `Box` slots, the walk's second `DOMMatrix` accumulator and the `current !== element` test that maintained it all go, paying for one exported function and a five-slot allocator. **It repeats no work**, which is the load-bearing mechanical claim: instrumenting `getComputedStyle` on a depth-12 chain gives **14 for the monolith and 13 + 1 for the split**, because `ancestry` starts at the flat parent and `coordinates` reads the element's own style once, which it already needed for the border-size fallback. At depth 15 the split is _faster_ than the monolith, 0.100 ms against 0.134. **The one-walk multi-`Space` form was built and declined.** It is the better runtime — one walk publishing both spaces costs 0.208 ms at depth 30 against two walks' 0.378, saving ~180 µs once per lift — but it costs **+22 B**, and it is the boundary parameter again under another name: a designated element, a second output, a per-node started flag and an all-or-nothing membership `false`. Every question BQ-7 spent an experiment closing returns with it, and the generality above two has no consumer, exactly as BQ-5 §6.4 and BQ-7 §3.4 found. **BQ-5 is re-evaluated rather than cited**: the retained-`Ancestry` objections do not transfer — a `Space` holds no element, so nothing is pinned and no boundary is located by identity; it is produced and consumed in one task like the `Box` beside it; and the cache it had to cancel against is gone. **BQ-5's decline of the retained, deferred-query form stands**; this form wins on grounds it never reached, and record 07 §5 priced shrinking `Box` to a pure measurement at ~+100 B where it here arrives at **−39 B against BQ-8**, because it is bought by deleting a concept rather than adding one. **Costs, stated rather than absorbed.** A new unenforceable precondition that **fails silently** — a row measured against a sibling subtree's space returns `true` with `a = 2` for a correct 1 and a width of 10 for a correct 20 — bounded by being explicit in the signature, by being the same class as `projection`'s already-documented same-viewport precondition, and by being **opt-in** under the optional form, which is why that form is settled. The measurement is **no longer bit-identical**, agreeing to 1–2 ULP because the ancestor product must close before the element's own node joins it; the association differs, no encoding avoids it, and the ancestor slots themselves agree exactly. And narrowing `Box` is a **breaking change** for drag2, which loses `BOX_ANCESTOR_*`. **One thing is recorded as possible and explicitly not claimed**: siblings share an ancestry, so one walk plus N measurements replaces N walks — 200 rows at depth 12 go from 18.6 ms to 1.9 ms, **9.9×** — but drag2's `rect-index` measures candidates with `getBoundingClientRect()`, not `coordinates()`, so nothing buys it today and it is not a ground. **Required properties**: `Space` is caller-owned numeric storage holding no element reference; producing one reads no layout and succeeds for an element with no principal box; `Box` carries only what `projection` reads; the split reads no more computed styles than today's single call and walks the flat tree once per element; the ancestry argument is **optional**, omitting it yields today's semantics, and its fallback storage must not be shared module state a re-entrant consumer-overridden `getClientRects` could clobber; the precondition is documented in `projection`'s own terms rather than enforced; and there is **no boundary, no designated ancestor and no cardinality** — a second space is a second `ancestry` call. | replaces a capability with a decomposition that costs less, deletes the boundary question permanently, and returns `Box` to the eight numbers `projection` reads |

## Record

### 2026-08-31 — the decomposition reconsidered: `Space` becomes first-class and the boundary disappears

BQ-8 rested on one fact: an element can have a well-defined inherited space and no measurable principal box. **The fact holds; the conclusion drawn from it did not.** It was true only because ancestry computation and box measurement were the same call, and the source already separates them internally.

**Publishing that seam is cheaper than the capability it justified.** `ancestry(element, out)` reads no layout and never touches the element's own box, so a `display: contents` element and one fragmented across four lines both answer correctly where `coordinates` returns `false`. `Space` is five numbers, `Box` falls to the eight slots `projection` actually reads, and the package comes out **+16 B** as consumed against BQ-8's +55 — **+34 end to end against +61** — because the change deletes five slots, an accumulator and a per-node test in exchange for one function. The split repeats nothing: 14 `getComputedStyle` calls for the monolith against 13 + 1 for the split, and at depth 15 the split is the faster of the two.

**The one-walk multi-`Space` form was built and declined**, and the reason matters more than the 22 B. It is the boundary parameter again under another name — a designated element, a second output, a membership `false` — so it buys back every question BQ-7 spent an experiment closing, to save ~180 µs once per lift. The point of the decomposition is that the model has no boundary in it.

**BQ-5 was re-run rather than cited**, as asked: a `Space` pins no DOM, defers no query and has no post-call lifetime, so none of the retained-`Ancestry` objections transfer, and record 07's ~+100 B price for a pure-measurement `Box` becomes −39 B when it is bought by deleting a concept instead of adding one. **The costs are recorded at full strength**: a silently-failing caller precondition, bounded by making the argument optional; a 1–2 ULP change that no encoding of the split can avoid; and a breaking `Box` narrowing for drag2. **The 9.9× sibling batch win is recorded as possible and explicitly not claimed** — `rect-index` measures with `getBoundingClientRect()`. **BQ-9** supersedes BQ-8, and **D-165** supersedes drag2's D-164, whose one-walk property this deliberately spends. Logged as **F-5**.

### 2026-08-31 — the boundary capability attacked at the root, and kept on one ground

The question was whether box-quad needs an ancestry boundary at all, given that `coordinates(visual, ·)` and `coordinates(item, ·)` already produce both spaces D-164 wants, back to back, in one task.

**The alternative won every column the argument was expected to turn on.** The second measurement reproduces the boundary walk **bit for bit**, so there is no numerical case for either side. The snapshot question dissolves: two consecutive statements admit no intervening layout, and the observed identity is what that predicts. It is **51 B cheaper** end to end — +9 against BQ-7's +60, with the full drag2 shape bundled in — and it deletes a public parameter, a variable-capacity allocator and a failure mode rather than adding them. Its runtime cost is a second style walk, +145 µs at depth 30 and +16 µs at realistic depths, once per lift, and **nothing at all** in the default composition, which never makes the second call. Bytes, runtime, numerics and temporal safety were all available to defend BQ-7 and none of them did.

**It loses on one fact, and it is a fact about what a space is.** `coordinates` refuses an element with no single principal box; the space _inherited_ by that element is defined anyway, because it belongs to the chain and not to the box. A `display: contents` item with a descendant visual, and an inline item fragmented across lines, both yield the correct answer from the boundary walk and `false` from a direct measurement. That shape is not exotic — it is the archetypal reason to name a `visual`, it works today because nothing measures the item, and the alternative would force drag2 to choose between refusing it and silently reinstating F-227.

**The check the encoding was expected to be defended on is discounted instead.** BQ-7 refuses a boundary off the visual's chain — a precondition its own derivation creates, which the alternative does not need and which therefore proves nothing. It is kept because the walk already knows when it passes the boundary, so the report is free and converts an unenforced invariant into a recognized refusal. **BQ-8** supersedes BQ-7 to make the load-bearing fact binding rather than incidental: the boundary space comes from the chain alone. Logged as **F-4**, because the test that decided this — name a configuration where the value is defined and the measurement is not — is cheap and general.

### 2026-08-31 — BQ-2's cardinality attacked; the limit upheld, the accidental one removed

The hypothesis was that several caller-known boundaries might come nearly free once output capacity is caller-owned. **It came back half right, and the two halves point opposite ways.**

**The runtime half is right, and it is recorded so BQ-2's successor is never defended on speed.** Eight boundaries at depth 30 cost no more than none — the arithmetic is a few multiplies per node against ~10 µs of `getComputedStyle`, and it simply does not register. N boundaries in one walk match N singular walks to 12 decimal places, from one observation with nothing retained. The multi-boundary form is a real primitive, not a contrivance.

**The cheapness half is wrong by 3×**, and instructively so: +52 B for one boundary against +165 for N, with two leaner dispatches coming out _worse_. The hypothesis correctly observes that caller-owned storage is free — and that is exactly why it does not help, because the cost is the per-node dispatch and the found-set, not the four slots per boundary. At +165 the arm lands within 7 B of the retained `Ancestry` BQ-5 declined, asking the same money for strictly less generality; and caller-owned variable capacity turns out to add a failure mode fixed cardinality cannot have, demonstrated both ways in a browser — a `RangeError` thrown after the first thirteen slots are already committed, or a silent dropped write returning `true`.

**But the experiment found a real defect, and that is what it was for.** BQ-2 fixed `BOX_LENGTH` at 17, so a later move to variable cardinality would have had to shrink `box()` and break every caller that passed a boundary. **The accidental limit was the allocator, not the cardinality.** **BQ-7** keeps cardinality one and spends **3 bytes** on `box(boundaries = 0)`, which also returns `Box` to 13 slots for the ordinary measurement and makes a future N purely additive. Its figures are also restated against the cacheless baseline BQ-6 leaves behind: **+55 B against BQ-6's −46, net −9**.

### 2026-08-31 — `cache()` attacked on utility, and removed

BQ-4 had just established that `cache()` was a deliberate later design rather than drift. That settles where it came from, and **this round tested whether it earns its place**, which is a different question that no prior decision had asked.

**It does not, and the reason is in the commit that created it.** Before `162f300fa`, `relativeTo` was an `HTMLElement` the library measured internally, and reusing that shared target across a batch is the entirety of artifact 5's _Shared reads_ and inverse-retention sections. That commit split the API and made `relativeTo` a caller-held `Box`. **The refactor that gave `cache()` its current form deleted the use case it existed for**, and the mechanism was carried across unexamined — deliberated about in form, never in utility. Logged as **F-3**, because the general rule is worth more than the instance.

**The measurement refused to make this easy, which is why it is worth trusting.** The browser gives no discount for re-reading an element, so a cache hit really is worth 676× — the mechanism is not a no-op and no argument here claims it is. But `out.set(kept)` is 7× faster than the hit and 4700× faster than a cold read, so **`Box` retention beats the cache on the cache's own best case**. The intuition this experiment was built on — that a cache only accelerates reads that were already cheap — was also **false**, and is not used: a read after a write costs only 36% more than a clean one. Both regimes are expensive; the point is that the cheaper remedy needs no state model.

**Removal is −46 B as consumed**, five times BQ-1's −9 because it takes the parameter, the discriminator and `Space.ownerDocument` and not just the callable — **more than paying for BQ-2's +40**. And it deletes **17% of the contract**: epochs, undetectable staleness, unenforceable entry opacity, adoption invalidation, weak-ownership and cross-document rules exist only because there is a cache, and BQ-4 had committed someone to rewriting all of it. **BQ-6** removes the mechanism instead, and names the two conditions that would bring it back.

### 2026-08-31 — Iteration D reopened: BQ-1 was wrong about which document had moved, and `Ancestry` is real but dearer

Two owner corrections. **The first is confirmed and BQ-1 is superseded.** BQ-1 called `cache()` undocumented drift against artifact 5; the commit order says the artifact is four days older than the symbol, and that the symbol arrived in a commit deliberately reshaping the public surface. The source is the later decision. **BQ-4** keeps the callable and turns the amendment around: artifact 5 is corrected, and the correction is not a rename — reset-in-place is the opposite of §2's "construct a new map", and it is the better arrangement for the long-lived holder a drag controller is. Logged as **F-2**, because the check that would have caught it is one `git log` per document.

**The second correction reopened the alternative on stronger terms**, and it deserved the prototype. Reframed as an `Ancestry` whose _retention is contract_ rather than an optional reuse strategy, it defeats the objection that decided BQ-3 — a value a consumer must read cannot come from something the contract calls unobservable — so it was built, cross-validated in a browser against BQ-2 on a non-commuting chain, benchmarked, and measured in three encodings.

**It works, and it is slightly faster.** Agreement to 1e-10, correct handling of a `display: contents` boundary, recognizable off-chain failure, no leakage between targets, and 3–10% quicker at depth 30 because its query is scalar where BQ-2 calls into `DOMMatrix`. That last is recorded deliberately: BQ-2 has no speed argument and must not be defended with one.

**It loses on cost and on ownership.** +137 B as consumed, +112 replacing the cache, and +101 even in the arm that shrinks `Box` from 13 slots to 9 by moving every chain fact out of it — a stable ~+95 penalty over BQ-2's +40, past the +68 the owner priced. And the deferral it sells has a price that cannot be engineered away: a boundary is located by identity, so the chain's **elements** are retained, making it the first caller-held object here that strongly pins DOM. It also opens a staleness window BQ-2 does not have, cancels against the cache, and serves an _n_ no caller needs — drag2 wants two spaces from one call and knows both before making it. **BQ-5** records all of it, including the strongest argument in its favour, so the question is closed on evidence rather than left to be re-proposed on intuition.

### 2026-08-31 — Iteration D opened on a challenge to D-164's encoding, and split three ways

The proposal was that box-quad stop owning the cache lifecycle, take a caller-supplied `WeakMap`, and memoize each visited element's style-derived linear facts — satisfying drag2's D-164 from the same traversal, deleting the `BoxCache` machinery, and coming out byte-neutral or smaller.

**It is three independent changes, and they separate cleanly.** Caller-owned map: accepted (BQ-1), and it turns out to be a contract _restoration_ rather than a proposal — the accepted contract has specified exactly that since 2026-07-26, and the shipped callable is undocumented drift. Explicit boundary: accepted (BQ-2), unchanged in substance from D-164, measured and suite-validated. Ancestor memoization: declined (BQ-3).

**The byte claim was measured rather than accepted, and it did not survive.** Five working arms, bundled with the repository's own Rolldown-plus-brotli pipeline, priced both whole-module and as drag2 actually consumes the package — the second figure being the one that counts, because `cache()` is tree-shaken from every shipped graph and its removal is therefore worth −9 B rather than the −34 the whole-module figure suggests. The proposal as put is **+68 B**, delivers no part of D-164, and makes the capability it was supposed to fund **dearer** rather than free.

**The decisive argument is not the bytes.** Artifact 5 §3 makes ancestor reuse explicitly _not observable behavior_ and §10 reserves the reuse strategy as changeable without an API revision. A value D-164 must be able to _read_ cannot come from there without permanently forfeiting that freedom — and the cache is optional, so a correctness guarantee would come to rest on a performance opt-in. Worse, an epoch promises layout has not changed, while `acquireLift` mutates the visual immediately after measuring it; any map drag2 held would be constructed for one call and discarded after reading one value out of it, which is a covert output parameter rather than a cache.

**One question was answered concretely rather than in principle.** One map _can_ hold both partial and complete entries — but only if a completed space is a strict superset of the per-element facts, plus a discriminator read. The naive shape is a silent wrong answer, shown in a real browser rather than argued: a parent's `scale(2)` disappears on the warm path with no exception, no `false` and no type error.

Documents and prototypes only; no production file was modified, and the five arms were built and measured outside the repository.
