## When to use

- Use for binary on/off states with button visuals.
- Use when pressed state should persist as `checked`.
- Use in segmented actions and settings toggles with text labels.

## When not to use

- One-shot actions. Use `mx-button`.
- Navigation actions. Use `mx-link-button`.
- Icon-only toggles. Use `mx-switch-icon-button`.

## Validation

The element has no native validators: its validity and its error display are both yours to set.

- **Validity:** `setCustomValidity(message)` makes the element invalid with a non-empty message, and valid with `''`. An invalid element blocks form submission and fires `invalid` at the host, which doesn't bubble. `validity`, `validationMessage`, `willValidate`, `checkValidity()` and `reportValidity()` behave as a native control's.
- **Error display:** the `error` attribute. While it is set, the switch matches `:state(error)` and its button is announced as invalid. Material defines no error appearance for it, so it draws nothing: style `:state(error)` yourself if you need one. No method, event, submission or reset sets or clears it.
- **`required`:** announces the control as required and does nothing else. It doesn't block submission and doesn't make `:required` match: validate in your own code, and select `[required]` in styles.
- **Form reset** leaves custom validity and `error` as they are. Clear them in the form's `reset` listener.
- Set `error` and `required` rather than `aria-invalid` and `aria-required` on the host.

To show the error once the user has tried to submit, as a native control does:

```js
field.addEventListener('invalid', () => {
  field.error = true;
});
field.addEventListener('change', () => {
  const message = validate(field);
  field.setCustomValidity(message);
  if (field.error) field.error = message !== '';
});
```

## Accessibility

- **Semantics:** Uses an internal native `<button>` with the `switch` role. Its `aria-checked` follows `checked`, unless the host has an `aria-checked`, which comes first.
- **Controlled:** Activation fires `click`, then `input`, then `change`, and changes no state. Set `checked` in a `change` handler to toggle the switch.
- **Keyboard:** `Tab` reaches the switch, and `Space` or `Enter` activates it.
- **Name:** Label text in the default slot provides the accessible name.
- **Disabled:** `disabled` removes the switch from the tab order and suppresses activation.

## Content guidelines

- Use clear binary labels that represent state meaning.
- Keep wording stable across checked and unchecked states.
- Use icons only as supporting cues, not as the sole state indicator.

## Anatomy

- `default` slot: label/content.
- `icon` slot: leading icon content.
- `impl` CSS part: internal native button with the `switch` role, which is the visual container and the focus target.

The label breaks between its words and never inside one, whatever `overflow-wrap` its container or the element has. To let it break inside words, set `overflow-wrap` on `::part(impl)`. `word-break` still applies.
