### Sortable lists

`mx-sortable-list` renders and styles like `mx-list`, takes the same items, and lets the user reorder them by pointer and keyboard. Import it from its own entry, `@ydinjs/material-x/list/sortable-list.js`, and install `@ydinjs/drag`, an optional peer dependency. A list that doesn't sort carries no drag code.

- An item with a `data-handle` child drags only by its handle, by pointer and keyboard. The list makes the handle a focusable _Reorder_ button. Unless the page sets its `display`, a handle other than an `mx-icon` is an `inline-grid` box that centers its content.
- A mouse drags an item without a handle by its whole surface, as does a pen that the browser doesn't scroll with. A finger on it scrolls instead, so give the items of a list that is used by touch a handle. A static `mx-list-item` without a handle becomes a tab stop in the sortable list only.
- The user can't reorder an item with `disabled`, by pointer or by keyboard, and other items move past it. Its handle isn't a tab stop and has `aria-disabled`. Disabling an item doesn't end a move that has begun. Other controls in the item stay enabled, dimmed with the item, and are the page's to disable.
- An arrow key moves the focused item, or the item of the focused handle, one slot. Mark a nested control that uses arrow keys itself, such as a text field, with `data-drag-ignore`.
- Each move fires a cancelable `reorder` event with `item`, `from`, `to`, `previous` and `next`. The list never moves an item: commit the move, for example with `list.insertBefore(event.item, event.next)`, in the handler or in a later render, or call `preventDefault()` to reject it.

## Anatomy

- `mx-list`: container for list items.
- `mx-sortable-list`: container whose items the user reorders.
- `mx-list-item`: static content item.
- `mx-list-button-item`: native button-backed action item.
- `mx-list-link-item`: native anchor-backed navigation item.
- Item slots, the same in the three items:
  - `lead` slot: leading icon, avatar, or image.
  - `overline` slot: overline text.
  - `default` slot: primary label text.
  - `support` slot: supporting text below the label.
  - `trail` slot: trailing icon, control, or text. A text that is too long wraps in at most half of the item. A control wider than half of the item is made narrower. In a narrow list, a control beside a wide leading child may be made narrower too, but never narrower than its longest word. A control of a page's own breaks inside its words unless the page sets `overflow-wrap: normal` on it. In a list as wide as its contents, a text wider than half of the item wraps too, so give such a list a width. Trailing children are side by side while together they fit in half of the item, and wrap to another line beyond that.

## Material 3 reference and deltas

- Material 3 overview: [https://m3.material.io/components/lists/overview](https://m3.material.io/components/lists/overview)
- Deltas:
  - One-line is the default; denser rows are inferred from slotted overline and supporting text.
  - Reordering is a separate element, `mx-sortable-list`, rather than a mode of `mx-list`. Its keyboard moves an item one slot per arrow key press, with no grab mode.
  - Reveal, expandable and segmented-list behavior are not included in this first implementation. Dividers are `mx-divider`, a direct child of the list between items.
