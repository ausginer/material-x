3. Which sessions it searches:
   - Te() is the session's originalCwd (offset 304612434).
   - vce(dir) (offset 315797020) runs `git worktree list --porcelain` in dir and returns every worktree path,
     the one containing dir first.
   - men(paths) (offset 316175393): with one worktree, it lists the current directory's project dir

   So a name is matched across all worktrees of the repository, not only the session's own directory.

Answers:
- Different directories: names are matched across every worktree of the repository, so the directory does
  not separate them. `Mx Implementer` and `Mx Implementer B` are different titles, so an exact match tells
  them apart. Two slots with the same letter can't exist, so slot names don't collide.
- Two sessions with one title: `--resume <name>` does not choose. It opens the picker with the name as
  its search text. A repeated `--init` with one name, and a /clear, each add a session with that title.
- `cl --init` can't refuse in advance: the CLI offers no command that lists session titles
  (`claude agents` lists running background sessions). So the documentation says to run `--init` once
  per slot and profile, and that the picker appears after a /clear.
