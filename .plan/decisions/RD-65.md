**Properties:**

1. **A private workspace package,** `@ydinjs/mutator` in `packages/mutator/`, with the CLI `mutator`. Nothing in it names material-x, its engine variable or this repository's recipes. `vitest` is its peer dependency. It is published only on the owner's word, when its format has held through a few reviews, and its API may change until then (`CONTRIBUTING.md` §8).
2. **A mutation file is data:** a TypeScript module whose default export is a plain object typed by the package, with no function in it. It names its runs, a package's directory and its test files, and its engines. Each mutation has a name unique in the file, its group in `RD-62` property 5's terms, one or more edits of _file, text, replacement_, and its expectation. An implementer's file is in its unit's `.plan/`, and a review's beside its report.
3. **The repository owns a config** at its root, read from the runner's checkout: the setup of a fresh copy, how each engine is selected, and, for files that a test reads built, a path pattern and the command that rebuilds them. A target whose harness differs runs with a config that matches it.
4. **Mutations are applied in a scratch copy at the commit run, never in the invoking checkout:** a detached worktree locally, a separate directory in CI. The copy is removed after the run, also after a failure. Each edit's text occurs exactly once at that commit, or the file is refused before anything runs, naming each stale edit. A rebuild that ran for a mutation runs again after its restore.
5. **An expectation is written before the run:** rows that fail, by test file and a text of the row's name, or _survives_, with its reason. It differs by engine only with a reason. Each outcome in an engine is _as expected_, _missed_, _caught_ or _void_. A selector that covers no row of the unmutated run makes the file invalid. The reviewer judges every outcome.
6. **Engines are compared:** a mutation that fails a different set of rows in one engine, counting only rows that ran in each, is flagged _differs_, unless a per-engine expectation gives the reason.
7. **A workflow that the reviewer dispatches,** `mutations.yml`, on `workflow_dispatch` alone, with `ref`, `file` and `shards`. The runner comes from the ref it is dispatched on, and the code from `ref`, in the engines that `ref`'s lockfile pins. One leg per engine and shard, each on its own runner, runs the unmutated files and then its mutations one at a time. A last job compares the engines and writes the summary, and it fails on any outcome but _as expected_ or any _differs_. It gates nothing, reads only `contents`, and has no secret. Nothing runs on a pull request by itself.
8. **The same CLI runs locally,** `mutator run <file>` with `--ref`, `--engine`, `--only` and `--config`, and gives the same reports. An implementer runs it in Chromium. A reviewer runs it to reproduce a leg or one mutation.
9. **After the review the file is the record,** with its report and summary saved in the review's `checks/`, because Actions artifacts expire. Nothing runs it again: its edits are valid at the commit it ran on. A recheck writes its own file.
10. **The runner's evidence:** node tests of the package on a fixture package, for each refusal, an unchanged invoking checkout after a run and after a failed one, each outcome, the engines' flag and a rebuild. **The acceptance run:** `RF-142`'s review runner rewritten as a file, run at `9173a25a1` in Chromium with every outcome as expected, dispatched in the three engines with the outcomes recorded as information, and one wrong prediction reported _missed_.
11. **The existing runners stay as they are,** as records of runs made (`RD-62` property 8). The acceptance rewrite is the only one.
12. **Not StrykerJS:** its Vitest runner doesn't support browser mode, it mutates no CSS or HTML, and it counts generated mutants where `RD-62` property 5 asks about the mechanism that a reviewer names.

**Units:** this one, on `repo/mutations-1`, has the package, its tests, the config, the workflow and the acceptance run, in one pull request that the implementer opens, and a feature proof. **Witness** of the workflow: the acceptance dispatch, and a dispatch of a file with a stale edit, which is refused before any leg runs a test. Then a documentation unit, after this one is on `main`, amends `RD-62` properties 1, 4 and 5, `test-architecture.md`, `reviewer.md` and `implementer.md`, as the plan says. `RD-62` Q1's interim answer, (a), holds until that unit merges.

**Costs:** a package's scaffolding and its tests; a workflow's minutes, which share the concurrency limit with `verify`; and a format that changes while it is private. **Not adopted:** a script in `.scripts/` (Q1 (c)), a mutation applied in memory by Vite, which misses what a test reads built, and a run of mutation files on each push. The plan has each.
