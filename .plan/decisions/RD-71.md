#### RD-71 — A choice among values is one enumerated attribute, never several booleans that can be set together

**Decided 2026-11-27 by the architect, on `repo/enumerated-attributes-1`,** on the owner's words relayed by the coordinator. `RD-70` is on `material-x/divider-1`, `RD-69` on `tproc/component-tables-1`, and `RD-65` and `RD-66` on `repo/mutations-1`. `material-x/select-1` proposes an `RD-69` in its plan without minting it. So this is the next free number. **It holds without code:** the rule is in [`attribute-vs-state-styling.md` §Public Attributes](../../.agents/docs/attribute-vs-state-styling.md#public-attributes), in this pull request.

**The owner's words,** translated by the coordinator. Answering the inset question of `mx-divider`'s [plan](https://github.com/ausginer/material-x/blob/c365f65a1/.plan/divider-1/divider-plan.md#q1--the-inset-attribute) (`RD-70`), he said: _"Three booleans mean all three can technically be set at once, and then how do you tell which one applies 😅 That's why I gave up booleans like that in mx."_ Asked whether to record it as a rule, he said: _"Yes, let's record it. It's an important parameter that I try to stick to."_

**Properties:**

1. **A choice among values is one enumerated attribute,** with one value for each option and the default when it is omitted. It is never several booleans that a page can set together.
2. **A boolean attribute is for one condition that is on or off,** such as `disabled`.
3. **It is a rule for every `@ydinjs/material-x` component,** and stated in force in `attribute-vs-state-styling.md` §Public Attributes. That section is where a component's attributes are ruled. The document has no change record, and nothing was stated before, so this record is the only history.

**Read against today's components,** at `2ed4b96ab`, every `@attr {boolean}` in `packages/material-x/src`:

- No two booleans of one component choose among values of one thing. The owner had already given them up, as he says.
- `mx-checkbox`'s `checked` and `indeterminate` can be set together. They aren't a choice among values: `checked` is the value, and `indeterminate` is how it is shown, as on a native checkbox, which keeps and submits `checked` while it is indeterminate.
- `mx-text-field`'s `outlined` and `mx-fab`'s `tonal` are each one boolean for a choice between two appearances. Property 1 doesn't reach a single boolean, because one can't be set together with itself. Whether those become enumerated attributes is not decided here.

**Why in that document.** It already states what an attribute is and what a state is, and `AGENTS.md` names it among the design references. `CONTRIBUTING.md` is about how source is written, and `architecture.md` about how a component is built from `@ydinjs/core`.
