#### RD-69 — tproc's converter stores a reference into another design system as upstream gives it, and checks every reference into Material 3's own

**Decided 2026-11-27 by the architect, on `tproc/component-tables-1`,** on the owner's answer to #335's question, relayed by the coordinator: he chose (a′). `RD-68` is the highest decision on any branch, `RD-65` and `RD-66` are on `repo/mutations-1`, and `material-x/select-1` proposes an `RD-69` in its plan without minting it, so this is the next free number. **Unimplemented.** The implementer of #335 implements it on this branch, with the 20th table. **Implemented** by #340. It supersedes, in part, `RD-28` property 5 and two of the plan's [converter checks](../tokens-source-1/tokens-source-plan.md#the-converters-checks), _References_ and _Child values_. The plan's [section](../tokens-source-1/tokens-source-plan.md#references-into-another-design-system) has the readings.

**Amended 2026-11-27, before merge, by the architect,** on `fp-3` of #340's [feature proof](../reviews/component-tables-1/feature-proof-claude.md#fp-3--tier-c-routed-to-the-architect-the-converter-reads-another-design-system-against-the-tables-own-system-where-rd-69-names-material-3s) at `c694c71b2`, relayed by the coordinator. Property 1 reads another design system against the table's own, which the table's `system.version.name` names, as the converter does. It used to name Material 3's id. What it said is at the end. **Implemented** by #340: its converter already reads it (`TableReader`'s `designSystem`), and no code changes.

- **The two readings agree on every table the store can hold.** The manifest's 38 tables record one database, version id `4ae102170fee99b1`, which is the version of the four system tables, Material 3's (`componentId` `20543ce18892f7d9`). A version belongs to one design system, so each table's own system is `designSystems/20543ce18892f7d9/`. A table of another system, such as _"Google Brand Colors"_ at version `v0.01`, has a `versionName` of its own, so the one-release refusal (`RD-28` property 2) already refuses it in an update.
- **The code's reading, because upstream states it in every table.** A table names its own system, so the converter reads that and doesn't need to carry a constant. The rows' fixture system, `designSystems/ds`, is then a table's own system, as it is in the code.
- **Not adopted: the converter names Material 3's id.** It would carry, as a constant, an id that each table gives. Every fixture would change to Material 3's id, and no table that the update converts would read differently.
- **Not adopted: a refusal of tables whose design systems differ.** The only case it would add to the one-release refusal is another system's table whose version has the same `versionName`. Converting another system's table is already not adopted below, and the manifest is changed only by a reviewed pull request. So the refusal would guard against an edit that nothing makes.

**What upstream gives.** The Progress indicators table, `TOKEN_TABLE.6f51f7ab7775a392` of release `2026-11-19_06-20-01`, database `41.1.12`, has 8 tokens that reach another design system: `md.comp.{linear,circular}-progress-indicator.four-color.active-indicator.{one,two,three,four}.color`. All are in the two `[Deprecated]` sets, and each has a `deprecationMessage`.

- Each has two values: a reference to `md.sys.color.*` tagged `audience: 3p`, and a reference to `goog.ref.brand-color.{blue,red,yellow,green}` with no tags.
- 56 tree entries, 7 per token and each tagged `audience: 1p.baseline`, reach `goog.ref.brand-color.*` at depth 1 and `goog.ref.brand-palette.*-500` at depth 2.
- Those tokens belong to design system `1b063509fc205e38`, _"Google Brand Colors"_, version `v0.01`, and not to Material 3's, `20543ce18892f7d9`. A tree node's value id says so: it starts `designSystems/1b063509fc205e38/`. A `values` entry has no such id of its own, only `name`, `tokenName` and `state`, and its own id is Material's.
- The release serves `COLOR.1b063509fc205e38.json`, which has the 4 `goog.ref.brand-color.*` tokens as literals. No table that the release serves carries `goog.ref.brand-palette.*`.

**Properties:**

1. **A reference into another design system** is a tree node whose value id names a design system other than its table's own, and every node below it. A table's own system is the one that its `system.version.name` names, and for every table of the store it is Material 3's, `designSystems/20543ce18892f7d9/`. A token's `values` entry references another system when a node of the same token's trees, with such an id, names the entry's `tokenName`. Any other reference is into the table's own system, Material 3's, including one that has no id to read. _(Amended 2026-11-27, above.)_
2. **It is stored as upstream gives it.** Its `tokenName`, `fieldNames` and child nodes are kept, as for any node. The node has no `value` index, because its token isn't in the store. The value id stays dropped, so the store gains no key, and `storeVersion` stays 2.
   - So every name in the store that names no stored token is a reference into another system. The converter has checked every other reference.
3. **It isn't checked.** Neither the reference check nor the child-value check applies to it. Every other check applies to its token and entry as before: the tree's root is the token's own value, the entry has one resolved form, its tags resolve, and the allow and drop lists rule each key.
4. **Every reference into Material 3's own system is still checked,** as `RD-28` property 5 says. A missing one refuses the update and names the table, the token and the field. A child node's value must still be a value of its token in the store.
5. **Selection doesn't change.** In the rendered context of `RD-28` property 9, each of the 8 tokens selects its `audience: 3p` entry, which references `md.sys.color.*`. No selected entry reaches another system, so the CSS layer reads none of these references.

**What the implementer does, on this branch:**

- narrows the two checks to property 1's references into Material 3's own system;
- adds two witnesses to the converter's tests:
  - **admitted:** a table whose token references another system's token, in a `values` entry and in a tree whose node has another system's value id, converts. The store keeps the name, and that node has no `value` index;
  - **still refused:** a missing reference whose node has Material 3's value id is refused with `names <token>, not in the store`. A `values` reference that no node of another system names is refused too;
- adds the 20th table, Progress indicators (`TOKEN_TABLE.6f51f7ab7775a392`), to the manifest, and converts the update again from release `2026-11-19_06-20-01`. The report lists its sets, material-x's 44 generated stylesheets stay byte-identical, and the transcript shows the 8 tokens' selected entries.

Each witness fails a converter that classifies by the wrong rule. The first fails today's converter, and the second fails one that admits every missing name.

**Why.** The other system's tokens are Google's brand colours, and they are reached only by `audience: 1p.baseline` entries. tproc renders `audience: 3p`, so it never reads them. Upstream gives the reference and its target's system, so storing it keeps the owner's _"fields and data stay original"_ (`RD-28`). A missing reference into Material 3's own system would still mean a broken table, so that check stays. The rule reads upstream's own id, so it doesn't depend on a name prefix such as `goog.`.

**Not adopted:**

- **Convert the other system's table too.** `COLOR.1b063509fc205e38.json` carries only the 4 `goog.ref.brand-color.*` tokens, as literals. The Progress indicators trees reach `goog.ref.brand-palette.*-500` under them, which no table that the release serves carries. And the store would hold a second design system that tproc doesn't render.
- **Leave the Progress indicators table out.** Its 3 current sets, `md.comp.progress-indicator`, `.circular` and `.linear`, with 38 tokens, would then be missing, though none of their tokens reaches another system.
- **Drop the 8 tokens, or their `1p.baseline` entries.** That stores less than upstream gives, against _"fields and data stay original"_.
- **Admit a reference by its `goog.` prefix,** or every missing one in a `[Deprecated]` set. Neither is a property that upstream states.

**Not decided:** a selected entry that reaches another system. None does at this release. If a later release has one, the update report shows the difference in material-x's CSS (`RD-28` property 6), and it is a new question. **What property 1 said until the amendment of 2026-11-27:** _"**A reference into another design system** is a tree node whose value id names a design system other than Material 3's, `designSystems/20543ce18892f7d9/`, and every node below it. A token's `values` entry references another system when a node of the same token's trees, with such an id, names the entry's `tokenName`. Any other reference is into Material 3's own system, including one that has no id to read."_
