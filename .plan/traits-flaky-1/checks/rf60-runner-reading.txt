## 1. Vitest returns a module's exports without checking a named import exists
# node_modules/vitest/dist/chunks/index.Bi0NXYPf.js
	/**
	* Vite checks that the module has exports emulating the Node.js behaviour,
	* but Vitest is more relaxed.
	*
	* We should keep the Vite behavior when there is a `strict` flag.
	* @internal
	*/
	processImport(exports) {
		return exports;
	}

So a named import that the module doesn't export reads as `undefined` where it is used.

`mod.exports` before evaluation ends is returned only when a module that `mod` imports,
still being evaluated, is on the requester's call stack. The generated trait modules
import only @ydinjs/core, and no core module imports a test module or a generated
consumer, so the row's imports have no such cycle.

A request is deduplicated only by its URL string while it is in flight. A server answer
with `invalidate: true` for a module the runner already holds resets its promise and
exports, and the next request evaluates the file again: a second module instance.
